DocQA 实施与验收

配套文档：项目申报书 · 技术设计说明书 · 答辩讲稿

1. 实施策略

1.1 一句话

AI 写代码，人做决策。

  • CodeAgent 负责：脚手架、解析器、索引器、CLI、Web、测试、文档初稿；
  • 人负责：问题定义、架构取舍、契约评审、指标口径、验收与答辩。

1.2 五步渐进

步骤名称定位状态退出条件
1doc2md基础必做已完成 Demo5 类格式可解析；图片有释义与溯源
2DocBase基础必做已完成 Demobuild/query/test 可运行；三路召回 + RRF + 精排
3AGENTS.md基础必做已完成 Demo约定四类；回答带 [n]；无据拒答
4Service可选扩展 · 团队级已提供实现watcher 可增量更新；事件可审计
5Web可选扩展 · 领域级已提供实现浏览器问答；引用可打开原文

1–3 步构建核心闭环，4–5 步面向团队与领域规模演进。

# 4) 问答：带轨迹

# 9) Web
./run.sh serve --open

# 10) 目录监控（单次）
./run.sh watch --src examples/docs --once

# 11) 测试

3.4 演示话术要点

  1. 先把「找不到文件」的痛点讲具体：只记得图、不记得文件名。
  2. 展示解析产物：data/parsed/02_分组转发设计/document.md 中图片已被替换为「图 + 释义 + 元信息」。
  3. 展示三路分数：query 输出中 dense/bm25/sparse/routes 同屏可见。
  4. 展示引用：回答末尾 [1] 可打开 #page=2&figure=1。
  5. 展示拒答：域外问题明确「无据不答」，并给最接近片段。
  6. 展示约定：打开根目录 AGENTS.md，说明这是「人与 Agent 的检索契约」。

5. 运维手册

5.1 日常

# 新增/修改文档后
./run.sh watch --src <文档目录> --parsed data/parsed --index data/index --once

# 或全量重建
./run.sh parse <文档目录> --out data/parsed
./run.sh build data/parsed --index data/index

5.2 索引备份/回滚

cp -r data/index data/index.bak.$(date +%Y%m%d)
# 回滚
rm -rf data/index && mv data/index.bak.YYYYMMDD data/index

索引目录自带 version 与 created_at，可用于审计。

5.3 模型切换

export DOCQA_MODEL_MODE=http
export DOCQA_BASE_URL=https://.../v1
export DOCQA_API_KEY=***
./run.sh build data/parsed --index data/index   # 换 Embedding 后必须重建
./run.sh doctor
切换 Embedding 模型后必须全量重建索引；build_index 会检测 vectors.json.model 并强制重算。

5.4 常见故障

现象排查
索引未就绪先 ./run.sh demo 或 build
图片未解析检查路径、扩展名；EMF/WMF 需先渲染
PDF 无文本扫描件需 OCR；pypdf 是否安装
回答总是无据覆盖率/相关度阈值过高；检查索引文档与分类
端点超时检查 DOCQA_BASE_URL；失败后会自动降级 Mock，重启进程恢复
Web 打开空白检查 data/index 是否存在；浏览器控制台/网络面板

6. 风险登记册

ID风险概率影响应对责任人
R1内部模型端点不可用中高Mock 降级 + 端点重试 + 告警开发
R2矢量图/扫描件信息丢失中中渲染扩展 + OCR 兜底 + 明示告警开发
R3页码估算引发误引用中中page_mode=estimated 明示；关键文档用 PDF/PPT产品
R4模型编造引用低高只允许真实 Chunk 引用；回答后重编号；拒答机制开发
R5敏感数据外泄低高本地运行、127.0.0.1、内部端点、密钥环境变量全员
R6规模增长导致检索变慢中中增量、批量、向量库替换点开发
R7演示语料与真实文档差异高中上线前用部门语料重建测试集产品
