## 独立聊天配置

```dotenv
DOCQA_CHAT_MODEL=deepseek-v4.1-flash
DOCQA_CHAT_BASE_URL=https://ai.gitee.com/v1
DOCQA_CHAT_API_KEY=
DOCQA_CHAT_MODE=mock
```

`DOCQA_CHAT_API_KEY` 留空时继承 `DOCQA_API_KEY`；`DOCQA_CHAT_BASE_URL` 留空时继承 `DOCQA_BASE_URL`。有效 Key 准备好后再将对应能力设为 `http`。更换 Embedding 后必须重建索引，聊天模型或 Key 变化不需要重建向量。

## 已验证的协议依据

- [Gitee 官方接口规范](https://ai.gitee.com/v1/yaml)：Embedding 为稠密浮点数组，结果按 `index` 对应输入；精排的 `top_n` 默认 3，因此项目显式请求全部候选。
- [官方向量化及精排说明](https://ai.gitee.com/docs/products/apis/embeddings/)：当前公开协议没有 BGE-M3 的 sparse lexical weights 输出，不能据普通 `embedding` 数组实现真正的学习型稀疏检索。
- [官方 DSH 集成文档](https://ai.gitee.com/docs/integrations/Development-Tools/deepseek-harness)：DeepSeek V4.1 Flash 的模型 ID 为 `deepseek-v4.1-flash`。

## 验证结果与后续

38 项单元/集成测试通过，覆盖向量排序、全候选精排、能力隔离、独立聊天鉴权、密钥脱敏、索引模型一致性和失败不覆盖旧索引。测试中的 HTTP 响应均为模拟，不代表本机令牌已通过鉴权。

有效令牌就绪后，启用需要的 HTTP 能力，先运行 `./run.sh probe`；全部所需能力验证通过后，备份原索引并全量建库，再重启 Web、运行检索评估。缺少真正 sparse 协议时继续使用明确标注的本地词法稀疏路。
