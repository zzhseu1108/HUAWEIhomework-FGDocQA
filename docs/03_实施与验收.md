## 1. 实施策略

### 1.1 一句话

**AI 写代码，人做决策。**

- CodeAgent 负责：脚手架、解析器、索引器、CLI、Web、测试、文档初稿；
- 人负责：问题定义、架构取舍、契约评审、指标口径、验收与答辩。

### 1.2 五步渐进

| 步骤 | 名称 | 定位 | 状态 | 退出条件 |
| --- | --- | --- | --- | --- |
| 1 | doc2md | 基础必做 | 已完成 Demo | 5 类格式可解析；图片有释义与溯源 |
| 2 | DocBase | 基础必做 | 已完成 Demo | build/query/test 可运行；三路召回 + RRF + 精排 |
| 3 | AGENTS.md | 基础必做 | 已完成 Demo | 约定四类；回答带 `[n]`；无据拒答 |
| 4 | Service | 可选扩展 · 团队级 | 已提供实现 | watcher 可增量更新；事件可审计 |
| 5 | Web | 可选扩展 · 领域级 | 已提供实现 | 浏览器问答；引用可打开原文 |

**1–3 步构建核心闭环，4–5 步面向团队与领域规模演进。**

## 2. 工作分解（WBS）

### 2.1 第 1 步：doc2md

| 任务 | 产出 | 验收 |
| --- | --- | --- |
| 格式识别与统一入口 | `detect_doc_type` / `parse_document` | `.md/.pdf/.docx/.pptx/.txt` 均可解析 |
| Markdown 图片处理 | 图片复制、重命名、引用替换 | 命名符合 `文档名_Page_Fig_标题` |
| PDF 解析 | 逐页文本 + 嵌入图 | 页码 exact；图片带图题 |
| DOCX 解析 | OOXML 段落/表格/图片 | 页码 estimated 明示 |
| PPTX 解析 | 幻灯片文本 + 图片 | 一页幻灯片 = 一页 |
| VL 释义 | `VLDescriber` + Mock | 释义写入正文引用块 |
| manifest | `manifest.json` | 包含图片、页码、统计、警告 |
| 失败处理 | warning / 明确报错 | 不静默丢数据 |

### 2.2 第 2 步：DocBase

| 任务 | 产出 | 验收 |
| --- | --- | --- |
| 语义切片 | `chunker.py` | 不跨页；代码块完整；超长段按句切 |
| 稠密索引 | `vectors.json` | 余弦召回可用 |
| BM25 | `sparse.json` 的 tf/df | 精确术语命中 |
| 稀疏索引 | 归一化权重 | 与 BM25 互补 |
| RRF | `retriever.py` | 三路结果可融合 |
| Reranker | 真实/Mock | 精排后 TOP-K 合理 |
| 增量建库 | 文档哈希 + chunk 复用 | 未变更文档不重算 |
| test 模式 | `evaluator.py` | recall@k / hit_rate / MRR |
| 降级 | route 级 try/except | 单路异常不拖垮全链路 |

### 2.3 第 3 步：AGENTS.md

| 任务 | 产出 | 验收 |
| --- | --- | --- |
| 四类约定 | `AGENTS.md` | 存在性/查询/溯源/产出 |
| Agent 主流程 | `answer.py` | 意图、检索、自评、生成 |
| 引用契约 | `Citation` | 文档名/页码/图号/链接 |
| 无据不答 | 阈值 + 拒答 | 域外问题不编造 |
| 多轮检索 | `max_rounds=2` | 不足时自动扩展 |
| 结构化产出 | Mermaid / 表格 / 步骤 | 与原文对照 |
| CLI | `ask/query/eval` | 可演示、可脚本化 |

### 2.4 第 4 步：Service（可选）

| 任务 | 产出 | 验收 |
| --- | --- | --- |
| 目录快照 | `_snapshot` | 新增/修改/删除可识别 |
| 增量解析 | `parse_document` | 仅变更文件重解析 |
| 增量建库 | `build_index(incremental=True)` | 索引版本递增 |
| 事件日志 | `data/watch.log` | JSONL 可审计 |
| 单次模式 | `--once` | 可用于 CI/手工触发 |

### 2.5 第 5 步：Web（可选）

| 任务 | 产出 | 验收 |
| --- | --- | --- |
| HTTP 服务 | `web/server.py` | 仅本机；无第三方框架 |
| API | `/api/ask` `/api/stats` `/api/doc` | 与 Agent 契约对齐 |
| 前端 | `static/index.html` | 问答、引用、原文抽屉 |
| Mermaid | 轻量 SVG 渲染 | 流程类问题图形化 |
| 响应式 | CSS media query | 窄屏可用 |

## 5. 运维手册

### 5.1 日常

```bash
# 新增/修改文档后
./run.sh watch --src <文档目录> --parsed data/parsed --index data/index --once

# 或全量重建
./run.sh parse <文档目录> --out data/parsed
./run.sh build data/parsed --index data/index
```

### 5.2 索引备份/回滚

```bash
cp -r data/index data/index.bak.$(date +%Y%m%d)
# 回滚
rm -rf data/index && mv data/index.bak.YYYYMMDD data/index
```

索引目录自带 `version` 与 `created_at`，可用于审计。

### 5.3 模型切换

```bash
export DOCQA_MODEL_MODE=http
export DOCQA_BASE_URL=https://.../v1
export DOCQA_API_KEY=***
./run.sh build data/parsed --index data/index   # 换 Embedding 后必须重建
./run.sh doctor
```

> 切换 Embedding 模型后必须全量重建索引；`build_index` 会检测 `vectors.json.model` 并强制重算。

### 5.4 常见故障

| 现象 | 排查 |
| --- | --- |
| `索引未就绪` | 先 `./run.sh demo` 或 `build` |
| 图片未解析 | 检查路径、扩展名；EMF/WMF 需先渲染 |
| PDF 无文本 | 扫描件需 OCR；`pypdf` 是否安装 |
| 回答总是无据 | 覆盖率/相关度阈值过高；检查索引文档与分类 |
| 端点超时 | 检查 `DOCQA_BASE_URL`；失败后会自动降级 Mock，重启进程恢复 |
| Web 打开空白 | 检查 `data/index` 是否存在；浏览器控制台/网络面板 |
