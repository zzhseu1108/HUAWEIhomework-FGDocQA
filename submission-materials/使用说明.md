# FGDocQA · 提交版使用说明

更新日期：2026-11-16
提交人：见班级个人材料文件夹

## 一、选择你的运行方式

| 方式 | 需要安装 Python | 需要 API Key | 建议用途 |
| --- | --- | --- | --- |
| Windows 可执行程序 | 不需要 | 不需要 | Windows x64 电脑直接验收 Mock 演示 |
| macOS 可执行程序 | 不需要 | 不需要 | 按 Apple 芯片或 Intel 芯片选择对应版本，直接验收 Mock 演示 |
| 源码版 | Python 3.9+ | Mock 不需要；API 模式需要 | 阅读源码、导入自己的文档、接入真实模型 |

先把整个提交包解压到可写文件夹，再启动程序。不要直接在压缩包预览器里运行，也不要只复制单个 `FGDocQA.exe` 或 `FGDocQA`；可执行文件旁的 `_internal` 和其他随附文件需要一起保留。

## 二、可执行程序的快速体验

### Windows x64

1. 解压 Windows 版本的完整程序目录。
2. 双击 `启动FGDocQA.bat` 或 `FGDocQA.exe`，进入同一个演示入口。
3. 首次启动会自动生成演示知识库，并在默认浏览器打开本机地址。
4. 保持程序终端运行，按下节步骤体验页面。

### macOS：按芯片选择

1. 在“关于本机”确认芯片类型，Apple 芯片选择 `macOS-Apple-Silicon`，Intel 芯片选择 `macOS-Intel`；解压相应版本的完整程序目录。
2. 双击 `启动FGDocQA.command`；也可在终端中运行 `./FGDocQA`。
3. 首次启动会自动生成演示知识库，并在默认浏览器打开本机地址。
4. 保持程序终端运行，按下节步骤体验页面。

以上成品默认强制使用 Mock，不读取原开发电脑的 `.env`，无需联网调用模型，不会下载大模型。若常用端口已被占用，启动器会选取可用端口；以终端实际输出的 `http://127.0.0.1:端口` 为准。

浏览器没有自动打开时，复制终端显示的本机网址手动访问。停止使用时，在程序终端按 `Ctrl+C`，并关闭浏览器页面。

首次生成的演示数据保存在用户可写目录，与程序目录分开：

- Windows：`%LOCALAPPDATA%\FGDocQA\demo-v1`。
- macOS：`~/Library/Application Support/FGDocQA/demo-v1`。

命令行可使用 `--help` 查看参数；`--no-browser` 仅启动服务而不自动开页面，`--data-dir "目录"` 可指定演示数据位置，`--smoke-test` 运行初始化与健康/问答自检后退出。

## 三、建议验收步骤

| 步骤 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 1 | 启动对应系统版本 | 浏览器显示 FGDocQA 与鲸鱼娘首页，模式为 Mock |
| 2 | 点击首页任一示例问题 | 返回回答，并展示来源或证据不足提示 |
| 3 | 点击回答引用 | 打开对应文档阅读器，能核对引用片段和图片信息 |
| 4 | 进入“知识文库” | 可以按分类查看文档、搜索内容与浏览原图 |
| 5 | 收藏一条回答或导出对话 | 收藏列表或导出的 Markdown 中保留回答与来源 |
| 6 | 问一个与演示语料无关的问题 | 系统提示依据不足，而非凭空给出业务结论 |
| 7 | 在程序终端按 `Ctrl+C` | 本机服务结束 |

随附示例包含 5 篇文档和 3 张图片，仅用于验证功能。对业务问题的判断应以页面给出的检索证据为准，不把演示答案当作真实设备操作建议。

## 四、运行源码版 Mock

进入源码文件夹。macOS / Linux / Windows WSL 的命令如下：

```bash
python3 -m venv .venv
source .venv/bin/activate
chmod +x run.sh
cp -n env.example .env
```

编辑 `.env`，确保以下五项均为 `mock`：

```dotenv
DOCQA_MODEL_MODE=mock
DOCQA_EMBED_MODE=mock
DOCQA_RERANK_MODE=mock
DOCQA_CHAT_MODE=mock
DOCQA_VL_MODE=mock
```

再运行：

```bash
./run.sh demo
./run.sh serve --open
```

需要解析 PDF 时，先执行 `python3 -m pip install -r requirements.txt`。完整命令、Windows 源码开发方式和文档导入方法，以源码根目录 `README.md` 为准。

## 五、接入自己的 API

成品可执行程序的默认入口用于稳定复现 Mock 演示。需要接入真实模型时，建议使用源码版并按其 `README.md` 的“API 模式”或“仅聊天接 API”操作：

1. 在源码根目录的 `.env` 填写 Base URL、有效 Key、准确模型 ID。
2. 分别将需要启用的 `DOCQA_*_MODE` 改成 `http`，未准备好的能力保留 `mock`。
3. 运行 `./run.sh probe`，确认所需 HTTP 能力真实返回成功。
4. 若切换了 Embedding 的模式、模型或维度，全量重建独立索引；首次切换不要使用 `--incremental`。
5. 启动时用 `serve --index` 指定对应索引，修改配置后重启后端。

只更换聊天模型、聊天 Key 或精排配置，不需要因此重建向量。更换视觉模型后，要重新解析再建库，单独建库不会补做图片释义。

Key 不随提交包提供。API 模式会向你配置的端点发送相应文本或图片；Mock 模式与真实服务的验证结果不能混同。

## 六、常见问题

| 情况 | 处理 |
| --- | --- |
| 双击后找不到页面 | 查看程序终端是否显示本机网址，复制网址到浏览器 |
| 启动后很快退出 | 重新在终端中启动，记录错误文字，并确认完整解压、保留 `_internal` |
| macOS 版本无法启动或提示架构不匹配 | 检查“关于本机”的芯片类型，换用 `macOS-Apple-Silicon` 或 `macOS-Intel` 对应目录；也可按源码说明运行 |
| 程序正在运行，但关掉浏览器后不知道如何打开 | 再访问终端输出的同一个本机网址 |
| 页面打开后无法连接服务 | 确认程序终端仍在运行；网址端口以本次启动输出为准 |
| Mock 回答不够自然 | Mock 使用规则和检索片段，体验真实生成需按源码说明接聊天 API |
| 填 Key 后仍显示 Mock | 检查各项模式开关并重启源码版服务，成品默认入口仍固定为 Mock |
| API 报 401 / 403 | 检查令牌所属平台、有效性和模型权限，不要添加 `Bearer ` 前缀 |
| 出现向量模型或维度不一致 | 切回建库配置，或全量重建对应索引 |
