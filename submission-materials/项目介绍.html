FGDocQA 是一个在本机运行的文档问答工作台，将 PDF、Word、PPT、Markdown 和 TXT 的正文及支持格式的内嵌图片整理成知识库。系统先检索相关片段，再给出附来源的回答，方便继续核对原文。

多格式 · 图文共同入库

正文解析、图片提取和图片释义保留来源元信息，支持按文档、页码和图片回看依据。

混合检索 · 兼顾词面与语义

稠密向量、BM25 与本地 TF-IDF 稀疏召回，经 RRF 融合和精排输出候选片段。

回答有据 · 证据不足会提示

展示引用和检索轨迹；有据时附出处，证据不足时返回“无据不答”。

浏览器工作台 · 开箱体验

提供文库、分类、阅读、图片预览、会话、收藏、复制与 Markdown 导出。

课程交付包含源码、Windows / macOS 可执行程序与介绍材料。成品内含 Python 运行时和演示资源，完整解压后启动，无需另装 Python 或准备 API Key。

两种模型使用方式
区别默认 Mock 演示HTTP API 模式
运行条件无需 Key，不下载大模型，适合离线验收配置可用端点、准确模型 ID 和相应凭据
模型能力哈希向量、词面精排、图注规则释义、片段式回答启用的能力调用真实 Embedding、Reranker、Chat 或视觉服务
验证方式程序自检与演示功能验证用 probe 验证所需能力；只填配置不等于连通

四类能力可分别切换，部分 HTTP、部分 Mock 时属于混合模式。第三路稀疏检索当前为 tfidf-local，没有接入 BGE-M3 的学习型稀疏权重。

建议验收顺序
完整解压 → 启动对应系统程序 → 确认 Mock 与鲸鱼娘首页 → 点击示例问题 → 打开来源与文库 → 收藏或导出 → 在程序终端按 Ctrl+C 结束。
验证与当前边界
  • 原有工程测试集为 38 项；HTTP 单测使用模拟响应，不代表云端鉴权成功。本次成品构建与自检以随包验证记录为准。
  • 面向个人本机使用，监听 127.0.0.1，没有多用户登录权限体系；会话与收藏保存在当前浏览器。
  • Mock 不代表真实语义模型效果；API 模式会向配置端点发送相应文本，启用真实视觉能力后还会发送图片。
  • DOCX 页码为估算，扫描 PDF 无完整 OCR 流程；示例业务语料为虚构场景。
