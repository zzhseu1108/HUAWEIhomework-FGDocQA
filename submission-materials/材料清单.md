## 交付内容

| 类别 | 应包含的文件 | 用途 |
| --- | --- | --- |
| 源码 | `src/`、`examples/`、`tests/`、`packaging/`、`README.md`、`env.example`、`pyproject.toml`、`requirements.txt`、`run.sh`、`AGENTS.md` 等 | 查看实现、复现开发流程与重新构建程序 |
| Windows 可执行程序 | Windows x64 的 `FGDocQA.exe` 与同目录 `_internal`、启动说明及随附运行资源 | 无需安装 Python，完整解压后直接体验 Mock |
| macOS 可执行程序 | Apple 芯片和 Intel 芯片两个版本，各含 `FGDocQA`、`.command` 启动脚本与 `_internal`、随附运行资源 | 按芯片选对应版本，无需安装 Python，完整解压后直接体验 Mock |
| 介绍材料 | `项目介绍.md`、便于阅读或打印的项目介绍文件、`使用说明.md`、本清单、`images/web-home-v2.jpg` | 了解目标、功能、架构、模式区别与验收方法 |
| 验证信息 | 本次构建与自检记录、归档校验信息 | 核对程序版本、平台和打包结果 |

可执行程序按 `Windows-x64/`、`macOS-Apple-Silicon/`、`macOS-Intel/` 区分。最终外层目录名和压缩包名，以提交包中的实际文件为准；各版本均含实际二进制与运行时，不能互换单个可执行文件。

## 源码保留与排除范围

保留业务实现、前端资源、演示语料、测试、构建脚本、依赖声明、操作说明和素材署名。默认演示知识库由程序首次启动生成，避免把开发电脑的绝对路径带入成品。

不包含开发机 `.env`、真实 API Key、虚拟环境、Git 仓库内部目录、Python 缓存、个人浏览器历史、运行日志和个人文档。`env.example` 只作为公开配置模板。

源码中的既有 `docs/`、`slides/` 若被保留，仅作开发过程与历史设计参考。本次课程作业介绍与验收，以本目录的新材料和源码根目录 `README.md` 为准，避免将旧竞赛身份、旧模型口径或历史测试数量作为当前状态。

## 验收入口

1. 快速体验：完整解压与本机系统匹配的可执行程序，按 `使用说明.md` 启动。
2. 查看原理：阅读 `项目介绍.md` 及源码中的 `src/docqa/`。
3. 检查 Mock / API：阅读源码 `README.md`，运行源码版的 `doctor` 与 `probe`。
4. 复现测试：按源码 README 的测试命令执行；真实 API 鉴权与模拟 HTTP 单测分别判断。
5. 上传班级材料文件夹：上传最终提交压缩包，保留本地副本与校验信息。
